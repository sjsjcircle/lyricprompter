# lyricprompter — 자동 가사 프롬프터

**가사 텍스트와 원곡 음원만 넣으면** 라이브 공연에서 가사를 자동으로 따라가는 프롬프터입니다. 한국어·일본어·영어를 지원하고, 한 곡 안에 섞여 있어도 됩니다. 그 밖의 언어는 지원하지 않습니다. 이탈리아어·독일어처럼 라틴 문자를 쓰는 언어는 경고 없이 영어로 처리되므로 타이밍이 크게 어긋날 수 있습니다([알려진 한계](#알려진-한계)).

[laurenceyoon/live-lyrics-tracking](https://github.com/laurenceyoon/live-lyrics-tracking)을 참고해 새로 설계·구현했습니다. 레퍼런스에서 손으로 하던 음절 분할과 타이밍 작업을 모두 자동화했습니다.

```
원곡 + 가사 ──▶ [준비] 보컬 분리 → 음절/모라 분할 → 강제정렬 ──▶ 줄·단어·음절 타이밍
라이브 오디오 ──▶ [추적] reference와 실시간 정렬(OLTW) + 자동 키 검출 ──▶ 프롬프터 화면 (karaoke wipe)
```

| 라이브 입력 (운영자가 선택) | 비교 대상 reference |
|---|---|
| **Full band mix**: 반주가 포함된 오디오(믹서 출력 등) | 원곡 전체 음원 `mix.wav` |
| **Vocal mic only**: 보컬 단독(보컬 마이크 채널) | 분리한 보컬 `vocals.wav` (옵션: 리드 보컬 `lead.wav`) |

## 설치 (macOS, Apple Silicon)

현재 설치 대상은 **Apple Silicon(M 시리즈) Mac의 macOS**입니다. 저장소의 `uv.lock`도 이 환경(`arm64`)을 기준으로 작성되어 있습니다. 최초 설치와 첫 곡 준비에는 Python·패키지·모델을 내려받을 인터넷 연결과, 모델 및 곡별 WAV 파일을 저장할 여유 디스크 공간이 필요합니다.

### 1) 터미널과 Homebrew 준비

**응용 프로그램 › 유틸리티 › 터미널**을 열고, 아래 명령을 한 줄씩 붙여 넣은 뒤 Enter를 누르세요. 다음 명령의 결과가 `arm64`인지 확인합니다.

```bash
uname -m
```

Homebrew가 없다면 [공식 홈페이지](https://brew.sh/)의 설치 명령을 실행합니다. 이미 `brew --version`이 작동하면 이 단계는 건너뛰세요.

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

설치 중 Mac 로그인 암호를 물으면 입력하세요. 암호는 입력해도 화면에 표시되지 않습니다. 설치가 끝나면 출력된 **Next steps**의 명령을 실행해 `brew`를 PATH에 추가하세요. Apple Silicon의 기본 설치 위치는 `/opt/homebrew`입니다. 새 터미널을 열어 다음 명령이 작동하는지 확인합니다.

```bash
brew --version
```

### 2) 필수 도구 설치

```bash
brew install git ffmpeg uv
```

`git`은 저장소를 받고 업데이트할 때, `ffmpeg`는 음원을 변환할 때, `uv`는 Python과 프로젝트 패키지를 관리할 때 씁니다.

### 3) 저장소와 Python 패키지 설치

설치할 위치에서 저장소를 받은 뒤 프로젝트 폴더로 이동합니다.

```bash
git clone https://github.com/sjsjcircle/lyricprompter.git
cd lyricprompter
```

이 프로젝트는 **Python 3.12**를 사용합니다(`.python-version`, `pyproject.toml`). [uv로 Python을 설치](https://docs.astral.sh/uv/guides/install-python/)하고, 저장소에 고정된 버전의 패키지를 설치합니다.

```bash
uv python install 3.12
uv sync --locked
```

`uv sync --locked`는 프로젝트 안에 `.venv`를 만들고 `uv.lock`에 기록된 패키지를 설치합니다. 잠금 파일과 프로젝트 설정이 맞지 않으면 파일을 임의로 갱신하지 않고 오류로 알려줍니다([uv 문서](https://docs.astral.sh/uv/concepts/projects/sync/)). 이후 명령은 모두 이 `lyricprompter` 폴더에서 실행하세요. `uv run`이 프로젝트의 Python 환경을 사용합니다.

### 4) 설치 확인과 첫 실행

```bash
uv run python --version
uv run lyricprompter --help
ffmpeg -version
```

Python은 `3.12.x`, 프롬프터는 `prep`, `serve`, `devices` 등의 명령 목록을 출력하면 됩니다. `ffmpeg`도 버전 정보를 출력해야 합니다.

이어서 서버를 시작합니다.

```bash
uv run lyricprompter serve
```

터미널에 시작 주소가 나오면 브라우저에서 엽니다.

- [콘솔 — 곡 추가와 공연 제어](http://127.0.0.1:8000/)
- [프롬프터 — 가사를 띄우는 화면](http://127.0.0.1:8000/prompter)

사용하는 동안 터미널을 열어 두세요. 종료할 때는 서버가 실행 중인 터미널에서 **Ctrl+C**를 누릅니다. 다음에 사용할 때도 프로젝트 폴더에서 같은 `serve` 명령을 실행하면 됩니다.

### 5) 내 음원으로 첫 곡 준비

저장소의 `songs/`에는 일부 곡의 타이밍 정보가 있지만 **실제 음원 파일은 포함하지 않습니다.** 목록에 보이는 예시 곡을 바로 재생하는 대신 내 음원으로 곡을 준비하세요.

1. 음원 파일(WAV, MP3, M4A, FLAC 등)과 실제로 부르는 순서대로 적은 가사를 준비합니다. CLI에서 가사 파일을 쓴다면 **UTF-8로 저장한 일반 텍스트 `.txt`**를 사용하세요.
2. 실행 중인 콘솔의 **Add song**에서 음원 파일을 선택하고 가사를 넣어 준비를 시작합니다.
3. 작업이 끝나면 곡을 선택하고 **Lines › Play**로 타이밍을 확인합니다. 명령줄로 준비하는 방법과 가사 형식은 [곡 준비](#1-곡-준비-자동-타이밍)를 참고하세요.

서버 화면을 여는 것과 곡을 준비하는 것은 별도입니다. 모델은 **첫 곡 준비 중** 필요한 시점에 자동으로 내려받으므로, 첫 작업은 이후 작업보다 오래 걸릴 수 있습니다. 기본 `--refine auto`는 Qwen3 모델이 이미 캐시에 있을 때만 보정하며, `--refine qwen`을 선택하면 필요한 모델을 내려받습니다.

별도 캐시 설정을 하지 않았을 때 모델 저장 위치는 다음과 같습니다.

| 용도 | 프로젝트 안의 기본 경로 |
|---|---|
| 보컬 분리 모델 | `.cache/models/audio-separator/` |
| MMS 가사 정렬 모델 | `.cache/models/torch/hub/checkpoints/` |
| 선택 사항인 Qwen3 보정 모델 | `.cache/models/hf/hub/` |

준비한 곡의 음원·가사·타이밍은 `songs/<id>/`에 저장됩니다. `.venv/`, `.cache/`, 곡의 WAV·FLAC 파일과 `lyrics.txt`는 `.gitignore`로 Git 관리에서 제외됩니다.

### 마이크와 오디오 인터페이스

실시간 마이크 입력을 사용할 때는 **시스템 설정 › 개인정보 보호 및 보안 › 마이크**에서 서버를 실행한 앱(터미널, iTerm 등)의 권한을 허용하세요. 오디오 인터페이스를 연결한 뒤 다음 명령으로 입력 장치를 확인할 수 있습니다.

```bash
uv run lyricprompter devices
```

서버가 실행 중이면 새 터미널에서 프로젝트 폴더로 이동해 실행하세요. 콘솔에서는 **Input › Audio interface**의 장치와 입력 채널을 고릅니다. 장치를 새로 연결했다면 세션을 멈춘 뒤 **Rescan devices**를 누르세요. 마이크 없이 확인하려면 내 곡을 준비한 뒤 **Recording (rehearsal)** 입력으로 녹음 파일을 사용할 수 있습니다.

### 설치 중 막혔을 때

| 증상 | 확인할 내용 |
|---|---|
| `brew` 또는 `uv`를 찾지 못함 | Homebrew 설치 후 **Next steps**를 실행했는지 확인하고 새 터미널을 여세요. `brew install uv`가 완료되었는지도 확인합니다. |
| `uname -m`이 `x86_64`로 나옴 | Apple Silicon Mac에서 터미널을 Rosetta로 실행 중인지 확인하고, `arm64`로 실행되는 터미널에서 설치하세요. |
| `pyproject.toml`을 찾지 못함 | `cd lyricprompter`로 저장소 폴더에 들어온 뒤 명령을 실행하세요. |
| Python 버전이 맞지 않음 | 프로젝트 폴더에서 `uv python install 3.12`와 `uv sync --locked`를 다시 실행하세요. |
| `ffmpeg not found on PATH` | `brew install ffmpeg`를 완료한 뒤 새 터미널에서 `ffmpeg -version`을 확인하세요. |
| `Address already in use` | 기존 서버를 Ctrl+C로 종료하거나 `uv run lyricprompter serve --port 8001`로 시작하세요. 브라우저 주소의 포트도 `8001`로 바꿉니다. |
| 장치가 없거나 입력 신호가 없음 | 위의 마이크 권한, 장치 연결, 입력 채널을 확인한 뒤 세션을 멈추고 장치를 다시 검색하세요. |

다운로드 중 연결이 끊겼다면 인터넷 연결을 확인한 뒤 실패한 `uv sync --locked` 또는 곡 준비 작업을 다시 실행하세요.

### 업데이트

서버를 Ctrl+C로 종료하고 **`songs/` 폴더 전체를 저장소 밖에 복사해 백업**하세요. 직접 고친 타이밍도 `song.json`에 저장되므로 음원만 복사하면 타이밍 수정은 보관되지 않습니다. 프로젝트 폴더에서 다음을 실행합니다.

```bash
git pull --ff-only
uv sync --locked
uv run lyricprompter serve
```

`git pull`이 로컬 변경이나 충돌 때문에 중단되면 `git status`로 변경 파일을 먼저 확인하세요. 곡을 보관하려면 강제 초기화나 파일 삭제로 해결하지 말고, 백업과 로컬 변경을 확인한 뒤 업데이트를 이어가세요.

## 1. 곡 준비 (자동 타이밍)

**방법 A — 웹 콘솔**: `uv run lyricprompter serve` 실행 → http://127.0.0.1:8000 → **Add song**에서 음원 파일과 가사를 넣습니다. 진행률은 왼쪽 목록에 표시됩니다.

**방법 B — CLI**:

```bash
uv run lyricprompter prep --audio song.m4a --lyrics lyrics.txt --title "꽃밭에서" --artist "조수미"
```

| 옵션 | 설명 |
|---|---|
| `--lang auto\|ko\|ja\|en` | 기본 언어. auto는 줄마다 판별합니다. |
| `--lead` | 리드 보컬도 따로 분리합니다(보컬 단독 모드에서 백보컬 영향을 줄임). |
| `--refine auto\|none\|qwen` | 신뢰도가 낮은 줄을 Qwen3로 다시 정렬합니다. auto는 모델이 캐시에 있을 때만 씁니다. |
| `--vocals stem.wav` | 이미 분리한 보컬이 있으면 분리를 건너뜁니다. |
| `--style classic\|pop` | 추적 스타일([아래](#추적-스타일-classic--pop)). 기본 classic이고, 다시 준비할 때 생략하면 기존 스타일을 유지합니다. |
| `--sep-model` | 분리 모델을 바꿉니다. 아래 **라이선스** 참고. |
| `--id <id>` | 곡 id(`songs/<id>/`)를 정합니다. 기존 곡의 id를 주면 그 곡을 다시 준비합니다. |

결과는 `songs/<id>/`에 저장됩니다: `song.json`(줄·단어·음절·음향 단위 타이밍과 신뢰도), `audio/{mix,vocals,instrumental}.wav`, `prep_report.json`.
4분 곡 기준 약 2분이 걸립니다(분리 약 1.5분, 정렬 약 10초, M5 Pro).

`--id`를 생략하면 제목으로 id를 만들고, 같은 id가 이미 있으면 `-2`, `-3`을 붙여 **새 곡**으로 추가합니다.

**가사를 고쳐 다시 준비하기**: 같은 명령에 `--id <기존 id>`를 붙여 실행하세요(id는 마지막에 출력되는 경로의 폴더 이름입니다).
- 음원과 분리 모델이 같으면 분리 결과를 재사용하므로 정렬만 다시 합니다.
- 모든 단계가 성공했을 때만 기존 곡을 교체합니다. 실패하면 기존 곡은 그대로 두고 오류를 `prep_report.failed.json`에 남깁니다.
- 콘솔에서 손으로 고친 타이밍은 새 정렬 결과로 바뀝니다.
- 웹 콘솔의 **Add song**은 항상 새 곡을 추가합니다. 다시 준비는 CLI로 하세요.

### 가사 입력 형식

| 형식 | 의미 |
|---|---|
| 한 줄 = 프롬프터 한 줄 | |
| 빈 줄 | 연(stanza) 구분 |
| `[Chorus]`, `[Verse 1]`, `후렴`, `サビ` | 섹션 머리말 (화면에는 나오지 않음) |
| `… x2`, `(2번)`, `(2回)`, `Repeat Chorus` | 반복. 부르는 순서대로 펼칩니다. |
| `(oh oh)` | 백보컬(정렬에서 제외하고 시간은 보간) |
| `漢字(かんじ)`, `{漢字\|かんじ}`, `｜漢字《かんじ》` | 후리가나. 의훈(宇宙=そら 등)은 이렇게 지정하세요. |
| LRC 파일 | 타임태그를 자동으로 제거합니다. |

**외국어 노래를 한국어 발음으로 띄우고 싶을 때**: 언어를 Korean(또는 Detect per line)으로 두고 한국어 발음 가사(예: `ありがとう` → `아리가토오`)를 넣으세요. 정렬은 로마자 기준이라 일본어 원문으로 준비한 것과 타이밍이 거의 같습니다. 일본어 줄과 한국어 줄을 **번갈아 붙여넣지는 마세요.** 두 줄 모두 부르는 줄로 정렬되어 타이밍이 크게 어긋납니다.

**음절 단위**: 한국어는 한글 한 글자, 일본어는 모라(한자는 읽기 모라 묶음), 영어는 CMUdict와 하이픈 규칙으로 나눈 음절입니다.

### 타이밍 검토

콘솔의 **Lines** 목록에서 줄마다 시작 시각과 신뢰도(Fit)를 볼 수 있습니다. 신뢰도가 낮은 줄은 빨간색 *low confidence*로 표시됩니다. 줄마다 쓸 수 있는 버튼은 다음과 같습니다.

- **Play**: 그 줄부터 원곡을 들어봅니다.
- **−0.1 / +0.1**: 줄을 0.1초씩 옮깁니다.
- **Set start**: 줄 시작을 플레이어의 현재 위치로 맞춥니다. 타이밍이 없는 줄도 이 버튼으로 타이밍을 줄 수 있습니다(음절당 0.25초, 최소 1초로 임시 배치).
- **Set end**: 줄 끝을 현재 위치로 맞춥니다. 시작은 그대로 두고 음절들을 비율대로 늘이거나 줄입니다.

수정하면 바로 `song.json`에 저장되고, 공연 중이면 프롬프터와 추적에도 바로 반영됩니다.

- **줄은 어디로든 옮길 수 있습니다.** 옮긴 줄은 리듬을 유지한 채 통째로 움직이고, 이웃 줄이 비켜 줍니다.
  - 다음 줄과 겹치게 된 줄은 다음 줄 시작 전에 끝나도록 꼬리만 잘리거나, 줄 전체가 비율대로 압축됩니다.
  - 줄 시작끼리는 최소 0.25초 간격을 둡니다. 그보다 가까워지는 이웃 줄은 필요한 만큼만 연쇄적으로 밀립니다(뒤 줄은 뒤로, 앞 줄은 앞으로).
  - 밀린 줄에는 *pushed* 표시와 검토 필요(빨간 줄)가 붙습니다. 시작 위치가 임시값이니 확인하세요.
  - 0초 앞이나 곡 끝 너머까지 밀어야 하는 수정만 거절되며, 알림에 어떤 줄 때문인지 나옵니다.
- **실행 취소**: Lines 머리의 **Undo** 버튼 또는 Cmd+Z(Windows: Ctrl+Z). 곡마다 최근 100번까지 되돌립니다. 서버를 다시 시작하면 기록이 사라지고, 다시 준비해서 가사 줄이 바뀐 뒤에는 되돌릴 수 없습니다.
- **Tap 모드**(여러 줄을 빠르게 맞출 때): Lines 머리의 **Tap**을 켜면 플레이어 위치 다음의 첫 줄이 파랗게 '대기' 상태가 됩니다.
  - 녹음을 재생하면서 줄이 시작될 때마다 **T** 키를 누르면 그 줄의 시작이 정해지고 다음 줄이 대기합니다.
  - 줄 번호(#)를 클릭하면 그 줄부터 다시 탭합니다. **Esc**로 끝냅니다.
  - 사람의 반응 시간(약 0.1–0.2초 늦음)은 보정하지 않으므로, 필요하면 −0.1로 다듬으세요.

## 2. 공연 (실시간 추적)

```bash
uv run lyricprompter serve                      # 콘솔: http://127.0.0.1:8000  /  프롬프터: /prompter
```

```bash
uv run lyricprompter serve --host 0.0.0.0       # 다른 기기(태블릿, 무대 모니터)에서 /prompter 열기
```

`--host 0.0.0.0`으로 실행하면 시작 메시지에 태블릿에서 열 주소(LAN IP, `<컴퓨터이름>.local`)가 함께 나옵니다. 콘솔에서 바꾼 프롬프터 표시 설정(거울, 글자 크기, 리드 타임 등)은 `songs/.display.json`에 저장되어 서버를 다시 켜도 유지됩니다.

- **Listen to**: `Full band mix` 또는 `Vocal mic only`를 고릅니다.
- **Style**: 곡의 추적 스타일(아래). 바꾸면 곡에 저장되고, 그 곡을 공연 중이면 바로 적용됩니다.
- **Input**
  - `Audio interface`: 장치와 채널을 고릅니다(1부터 시작하는 번호, 여러 채널을 고르면 다운믹스).
  - `Recording (rehearsal)`: 녹음 파일을 실시간 속도로 재생해 리허설합니다. `Play through speakers`를 켜면 소리도 함께 납니다.
- **Session**: Start / Stop / Hold, 시작 줄 선택, ±0.5 s 미세 조정, 줄 목록의 **Go**로 바로 이동.
- **Adjust**
  - **Key — Auto**(기본): 처음 6–10초 동안 라이브의 키를 자동으로 찾습니다.
    - 반주가 있으면 확실하게 잡습니다.
    - 목소리만 있을 때 애매하면 키를 바꾸지 않고 `+2?` 같은 제안만 띄웁니다(클릭하면 적용).
    - 키를 손으로 정하면 Auto는 꺼집니다.
  - **Latency (ms)**: 출력 지연을 보정합니다.
- **Prompter**: 보기 방식(Layout), 한 화면 최대 줄 수(Max lines), 음절 하이라이트(Syllable highlight), 리드 타임(다음 줄을 미리 보여주는 시간), 글자 크기, 다음 줄 개수, 거울 모드(프롬프터 유리용).

### 추적 스타일 (classic / pop)

곡마다 고릅니다. **Add song** 양식의 `Tracking style`, 콘솔 Session 칸의 `Style`, CLI `prep --style`에서 정할 수 있습니다.

| 스타일 | 맞는 곡 | 동작 |
|---|---|---|
| **Classical — flexible tempo** (`classic`, 기본값) | 클래식, 루바토, 템포가 자주 바뀌는 곡 | 지금까지의 방식. DTW로 음절 하나하나를 따라갑니다. 가수가 줄을 부르지 않으면 vocal 모드에서는 다음 줄 시작에서 기다립니다. |
| **Pop & band — steady tempo** (`pop`) | 밴드, 록, 대부분의 팝 | 밴드 템포로 계속 진행하고 DTW 결과로는 조금씩만 보정합니다. 관객이 대신 부른 줄, 애드리브, 놓친 음절이 있어도 멈추거나 다음 줄에서 기다리지 않습니다. |

- **pop의 한계**
  - 템포가 실제로 바뀌는 부분(자유로운 인트로, 템포가 바뀌는 브리지, 끝의 ritardando)은 몇 초 늦게 따라갑니다. 이런 곡은 classic이 낫습니다.
  - 곡 구조가 바뀌면(절 건너뛰기, 후렴 반복) classic보다 복구가 약 5초 늦습니다. 급하면 Go로 옮기세요.
  - vocal 모드에서는 첫 줄을 부르기 전, 그리고 목소리가 없을 때 Go로 옮긴 직후에는 classic처럼 그 줄에서 목소리를 기다립니다.
- `simulate --style pop`으로 시험할 수 있습니다(기본은 곡에 저장된 스타일). 설계와 평가는 [docs/eval/TRACKING.md](docs/eval/TRACKING.md) §8에 있습니다.

### 프롬프터 화면

**프롬프터 화면**(`/prompter`)은 서버가 보내는 위치와 템포로 60 fps 보간합니다. 오프라인 환경(CDN 없이)에서도 동작합니다. 보기 방식은 두 가지입니다.

- **Line by line**(기본): 현재 줄을 크게 보여주고, 다음 줄은 미리, 이전 줄은 흐리게 보여줍니다.
- **Multiple lines**: 한 화면(페이지)에 여러 줄을 보여줍니다.
  - 가사의 빈 줄 하나가 문단 구분입니다(`[Chorus]` 같은 섹션 머리말도 새 문단). 한 문단이 한 페이지가 됩니다. 짧은 문단끼리 합치지는 않습니다.
  - **Max lines**(1–8, 기본 4)보다 긴 문단은 고르게 나눕니다. 큰 페이지가 먼저 옵니다(Max 5에서 11줄은 4/4/3, 5/5/1이 아님).
  - 예: Max 5에서 4줄씩 나눈 가사는 4줄씩 보입니다. 문단 구분이 없는 20줄은 5줄씩, 12줄은 4/4/4로 보입니다.
  - 지금 부를 줄은 흰색과 왼쪽 노란 막대로, 이미 부른 줄은 어두운 회색, 아직 부를 줄은 밝은 회색으로 보입니다. 페이지 안에서는 줄 위치와 글자 크기가 그대로이고 색만 바뀝니다.
  - 글자 크기는 페이지가 화면에 다 들어가는 가장 큰 크기로 자동으로 맞춥니다. Text size는 이 모드에서 최대 크기입니다.
  - 페이지는 리드 타임만큼 미리 넘어갑니다. Upcoming lines는 다음 페이지 첫 줄들을 구분선 아래에 작게 보여줍니다.
- **Syllable highlight**(기본 켜짐): 지금 줄이 음절 단위로 노란색으로 차오릅니다(karaoke wipe). 끄면 지금 줄이 밝은 흰색 그대로 보입니다. 콘솔의 작은 미리보기는 이 설정과 상관없이 하이라이트를 유지합니다.
- **프롬프터 단축키**: F 전체 화면, L 보기 방식, W 음절 하이라이트, M 거울, +/− 글자 크기, S 설정. 프롬프터에서 바꾼 값은 그 화면에만 적용되고, 콘솔에서 같은 설정을 바꾸면 콘솔 값을 따릅니다.

**터미널에서 시뮬레이션**:

```bash
uv run lyricprompter simulate --song edelweiss --file other_take.wav --mode mix
```

- 기본은 자동 키 검출이며, 키가 바뀌면 출력에 표시됩니다.
- `--transpose 2`: 키를 고정합니다(자동 검출 끔).
- `--transpose 2 --auto-key`: 2를 시작점으로 자동 검출합니다.
- `--no-auto-key`: 원래 키 그대로 고정합니다.

```bash
uv run lyricprompter devices                    # 입력 장치 목록
```

## 3. 성능 (평가 데이터 기준)

| 항목 | 결과 | 문서 |

| 가사 정렬 (영어 실제 곡 6곡) | 단어 시작 오차 중앙값 0.06–0.23 s, 0.3 s 이내 55–93% (어려운 팝 2곡 55–72%, 나머지 4곡 80–93%) | [docs/eval/ALIGNMENT.md](docs/eval/ALIGNMENT.md) §3 |
| 가사 정렬 (한국어 꽃밭에서, pseudo-GT) | 음절 오차 중앙값 0.23 s, 1 s 이내 88% | 〃 |
| 가사 정렬 (일본어) | TTS로만 검증, 평균 오차 0.014 s (노래 GT 없음) | 〃 |
| 실시간 추적, mix (13쌍) | 위치 오차 0.3 s 이내 87.8%, 1 s 이내 96.5% | [docs/eval/TRACKING.md](docs/eval/TRACKING.md) |
| 실시간 추적, vocal (11쌍) | 0.3 s 이내 91.6%, 1 s 이내 97.4% | 〃 |

| 합성 밴드 공연(템포 일정, 줄 누락·애드리브 포함, 6곡) | 0.3 s 이내 classic → pop: mix 79.6 → 92.0%, vocal 66.3 → 85.9% (1 s 이내 pop 100 / 99.5%) | 〃 §8 |
| 템포가 바뀌는 기존 평가 쌍에서 pop | 0.3 s 이내 mix 87.9 → 72.7%, vocal 91.7 → 81.8% (classic이 나음) | 〃 §8 |
| CPU | 특징 추출 + 추적이 프레임(40 ms)당 1 ms 미만 | |

평가는 다음 명령으로 다시 돌릴 수 있습니다.

```bash
uv run lyricprompter eval-align
```

```bash
uv run lyricprompter eval-track
```

평가에는 레퍼런스 repo 클론(`./live-lyrics-tracking`)의 음원·주석과 `data/` 아래 테스트 세트가 필요합니다.

## 알려진 한계

- **정렬**
  - 일본어 노래 정답 데이터가 없어 일본어는 TTS로만 검증했습니다.
  - 일본어 동형이음어·의훈은 `needs_review`로 표시만 하므로 후리가나로 지정하세요.
  - 어려운 팝(빠른 랩, 겹치는 코러스)에서는 일부 구간이 수 초 어긋날 수 있습니다. 대부분 저신뢰로 표시되니 검토 화면에서 고치세요.
  - **한국어·일본어·영어 외의 언어**는 지원하지 않습니다. 이탈리아어·스페인어·독일어·프랑스어 같은 라틴 문자 가사는 경고 없이 영어로 판별되고 영어 규칙으로 음절을 나눕니다(예: `pianga` → `pi/anga`).
    - 줄 시작이 수 초에서 수십 초까지 어긋날 수 있습니다.
    - 크게 어긋났는데 저신뢰로 표시되지 않는 줄도 있습니다. 저신뢰 줄만 보지 말고 **모든 줄을 Play로 들어보며** 확인하세요.
- **보컬 단독 모드 + 조옮김 공연**: 목소리만으로 이웃 키를 확실히 가리기 어렵습니다. 자동으로 키를 바꾸지 못할 수 있고, 제안이 뜨기까지 30초 넘게 걸릴 수도 있습니다(실제 Edelweiss 보컬: 36초). 키를 알면 미리 정하고, 아니면 콘솔의 제안을 확인하세요.
- **극단적인 템포 차이**: 원곡의 3배 이상 빠르거나 2배 이상 느리면 정확도가 떨어집니다. 노래 구조를 크게 바꾼 경우(건너뛰기·반복)는 전역 재탐색으로 복구되지만 몇 초 걸립니다. 운영자 점프(Go)가 가장 확실합니다.
- **보안**: 서버에는 인증이 없습니다. `--host 0.0.0.0`은 믿을 수 있는 무대 네트워크에서만 쓰세요.

## 라이선스 메모

- **기본 분리 모델** `bs_roformer_vocals_resurrection_unwa.ckpt`는 라이선스가 명시되어 있지 않습니다. 배포·상업 용도라면 MIT인 `--sep-model vocals_mel_band_roformer.ckpt`를 쓰세요.
- **`--lead` 모델**(becruily karaoke)도 라이선스가 명시되어 있지 않습니다.
- **audio-separator**는 MIT입니다. macOS에서 함께 설치되는 diffq는 CC BY-NC입니다(Demucs 경로에서만 사용).
- **레퍼런스 repo**(`live-lyrics-tracking/`)는 비공개이고 라이선스가 없습니다. 코드와 모델은 복사하지 않았고, 음원·주석은 로컬 평가에만 씁니다. 커밋하지 마세요(.gitignore 처리됨).
